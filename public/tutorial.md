截至核对时建议ID分别为 `deepseek-v4-pro`、`doubao-seed-2-1-pro-260915`、`qwen3.8-max`。模型开通权限、地区、接入点和价格可能变化，以自己账户的官方控制台为准，不要照抄不存在的型号或0价格。

## 接入步骤

1. 到各自开放平台创建API Key、开通当前可用的文本模型；聊天App密码不是API Key。
2. 在「模型设置」先填写策划服务商、模型、密钥和最高输入/输出价格；在「按角色分配模型」分别填写作者与审核配置。不同平台不能混用密钥。独立角色必须有自己的模型和价格；留空服务商才沿用策划账户、密钥和最高单价。
3. 单价统一为人民币/百万token。元/千token乘1000；美元报价自行按已核实汇率换算。共用一组价格的多个型号，应填写其中最高价格。不要把免费试用额度当成永久价格。
4. 千问接入使用北京兼容接口；如账户要求业务空间专属域名，填写控制台中的北京业务空间ID，不填写URL。其他地区或不兼容协议未验证，不能随意改接口地址。
5. 设置月度、全局单书、单次请求、可选单章上限；每本书另有自身预算，取更低限制。最后明确勾选费用授权并「保存全部模型配置」。修改角色配置后需重新核对费用勾选；旧运行任务会因配置版本变化停止。
6. 保存后可分别点击三个角色的「测试连接（可能计费）」；每次至多64输出token，也会受授权和预算限制。连接成功不代表能完成长章或达到文学质量。

## 启动与写作流程

1. 创建作品，设定方向、主平台、总章数、每章汉字数和单书预算。先用新增三章的小批次验证，不必直接启动整本书。
2. 本人点击「启动云端创作」。当前后台自动调度暂停，可使用「在此页一键连续执行」并保持页面打开；最多80检查点或20分钟。重新打开查看最近心跳，排队不等于后台正在执行。页面刷新只读取数据。
3. 新建的长篇先存故事骨架和首批至多10章详纲，立即开始验证正文；后续根据真实定稿后果和阶段意见继续细化，不提前花费整本细纲。旧作品按原流程续写，保留原计划和已开始章节。
4. 每章由策划先写清上一章处境、当前行动原因、各场景的阻碍/选择/代价、必须改变的事实、禁止变化和相关旧章。作者读取上一章结尾、相关旧稿原文、完整当前事实及活跃伏笔，再分段写作。
5. 程序先做不调用模型的字数/明显重复检查，再交审核角色全文审稿。85分、三项核心各14且原文证据、场景后果、事实变化全部通过才锁定。首三章还需联合验收，每十章需要逐章证据的阶段审核。
6. 可局部解决的缺陷由作者生成补丁，保留原版和未修改文字，再重新全文审核。最多三轮；范围过大、结构问题、虚构引用、预算不足或错误会停止。软件不会无限自我优化消耗费用。

新章节默认按1600汉字分段；可选择1000–3500。较大的分段可能减少重复输入，也可能增加截断风险。已开始的任务书不受这项设置变化影响。自动局部返修最多6处，总修改范围不超过正文40%（短章至少1200字符）；超出需检查结构或建立暂停的独立修订副本。本人主动整章修订属于另一条明确收费操作。

## 故事控制台与高级检查

从左侧「故事控制台」或创作首页入口进入，可以看到读者体验承诺、主题问题、结局代价、当前阶段、接下来三章、伏笔期限、人物最近选择及原文、旧稿对照和真实定稿评分轨迹。查看面板不会调用模型，空记录不代表已完成文学验收。

新建作品自动使用高级规格；原作品和旧备份按原流程继续，不被强制升级或重跑付费审核。策划为核心人物分配稳定ID，每章明确焦点人物的欲望与取舍。到期埋设/兑现的伏笔必须进入任务书，编辑用实际原文核验。已兑现项不能重新打开，事件不能改掉原承诺和最迟期限。计划同章必需动作最多40项，超限先检查计划，不自动延期。

反重复审稿需要本章与本轮实际提供旧稿片段的原文对照；发现重大结构重复或资料不足会停止，不让作者付费编造区别。焦点人物可通过关系、认知或立场变化推进，安静章节无需强行反转。高级备份在导入前会重新做程序证据检查，仍默认暂停，不请求模型。

## 费用和进度

「合格定稿成本」按环节展示调用、最高配置单价记账和待核对费用，并分摊到每万字正式定稿。包含失败尝试、规划和审核，不能只看写正文单次价格。未使用缓存优惠压低预算，实际账单到供应商核对。

单章上限包含本章任务书、正文、返修与复审；全局规划、开篇及十章联合审核归入单书/月度预算。软件尚未为未来全部审核预先锁定整书资金，达到上限可能留下待审稿件；不会为完成目标擅自提高预算。

未知用量、超时或不确定请求按最高预留保守记账；已返回usage的截断输出会按已知用量记账。网络不确定时不自动重放付费请求。预算不足时本人可暂停后修改作品预算；保存预算不会自动启动任务。

## 大纲、修订和备份

- 修改未来大纲前先暂停，等待在途检查点结束。只能修改尚未开始的章节/阶段，不能覆盖定稿事实；保存后由本人检查并重新启动。
- 未来远期细纲变化不会让相同开篇重复付费审核；影响开篇或当前阶段的设定、人物、目标、标题、正文变化会使旧结论失效。
- 审核失败查看原文证据。结构性问题可创建独立修订副本，原稿保留，副本默认暂停；不要降低质量门来换取通过。
- 定期下载完整JSON备份。包含正文、任务书、历史、审核和大纲，不包含API密钥。恢复创建独立暂停副本；恢复尚未完成时不能启动。导入的开篇/阶段联合审核结论须重新核验，不直接复用旧PASS；原有单章审核随稿保留。
- TXT下载不等于发表。「投稿材料」还要求当前开篇验收、本人核实的官方AI适用政策及格式。软件不替你投稿、签约或授权版权。

## 常见问题

| 状态 | 处理 |
|---|---|
| 401 | 检查该角色自己的密钥与服务商、业务空间，不要把密钥发送到聊天。 |
| 403/404 | 核对模型完整ID、开通权限、地区和业务空间。 |
| 429 | 检查供应商额度/限流，处理后本人决定重新启动；不会自动无限重试。 |
| 预留超额 | 核对最高单价、上下文与输出上限；不要盲目填0价或替换模型。 |
| 输出截断/JSON或证据错误 | 旧稿保留，先检查模型能力和输出上限。程序不付费递归修复JSON，也不改小说迎合假引用。 |
| 返修超限/结构阻塞 | 根据任务书和证据检查人物选择、因果、场景设计，使用修订副本；不自动重启。 |
| 心跳过期 | 当前后台调度暂停，使用前台批次并保持页面打开，不能承诺关闭后继续。 |

113项程序测试及构建Worker接口检查均为本地真实数据库/协议验证，正文采用标明的合成夹具。本轮没有调用真实供应商、没有产出或通过真实样章；文学质量、连续长篇、手机实机和实际平台竞争力仍需验证。任何模型分数都不能保证签约、保底或收入。

## V0.7：先核对平台与算力，再创作

在「平台与规则」选择番茄、七猫、起点或豆瓣阅读，查看官方要求/编辑建议/未知条件。新建书自动绑定规则版本；已有书无正文可点击核对并绑定。规则更新后旧任务停下，不自动开费或重启。豆瓣阅读目前禁止本自动正文创作方式；其他三站不默认允许整本AI正文投稿。

「收入与成本」新增90万字估算，可切换为本人保存的三角色单价。V0.8 DeepSeek主写参考组合的较省/常规/较重约223/451/1102元，实际按usage和预算限制，默认20元不是整本完成价。

每10章总审阻止未通过的下一章。在「验收与投稿」选择最早受影响章建立独立修订副本，可保留起始章手修稿待审。下游旧稿与受影响验收失效；未改前缀哈希相同才复用验收。新稿通过全文审核后重新锁定，作者仍可读，后章按新定稿与事实续写。起始章核心任务需改变时取消保留稿，重新创作；旧格式大纲不兼容时先改未来计划。

「小说工作室」给自然表达提示与朱雀官方入口。提示不判断AI身份；当前未接入检测API，不会外发稿件，不承诺通过检测。风格修订和检测分不能替代平台政策、人工编辑及真实签约。


## V0.8：DeepSeek主写与四份故事档案

主写改为DeepSeek V4 Pro，策划继续DeepSeek，独立审核建议Qwen；这里是角色分工，尚未实测证明哪家中文小说最好。正文、局部返修、重写关闭DeepSeek默认思考，策划保留原模式。点击「将已保存主写切换为DeepSeek」复用已存DeepSeek密钥，仅改作者及9/27高峰参考最高单价，不开费、不提预算、不启动任务；旧活动任务因配置版本变化停下，由本人检查后决定启动。没有DeepSeek key会明确提示补齐，不回退豆包。

「故事控制台」的四档案是世界/事实、人物/实际选择、计划/真实后果、伏笔/兑现。只有连续定稿事件进入当前状态，来源附hash与原文。作者和策划读取当前相关人物最近选择与最后已成立转变，避免初始人设覆盖成长；最多四名相关人物，非全书人物所有细节永久记忆。

新书新增读者定位、阅读回报、差异、剧情单元与人物行为/改变条件；每章写明读者已知、期待、当章回报、后续承接，每段写明stopAfter/defer，避免抢跑后续。一个剧情单元可跨分段或章，不要求每段独立高潮。9000字目标不自动改为图中的2500–3000字；平台发布篇幅另行核对。

审核引用原文检查焦点人物、世界和逐段边界。资料不足或无依据突变先阻塞诊断；局部问题按原上限返修并全文复审。真实引用与内部评分都不能证明文学质量，需先验三章、再十章，并收集真实编辑/读者意见。不存在永久不崩、秒签、保底保证；详情见软件教程的创作方法与来源。


## V0.9：参考与文风

1. 选择或创建作品，在手机菜单打开「参考与文风」。导入TXT/Markdown，或粘贴片段。UTF-8、GB18030、带BOM的UTF-16在本机解码；整本文件只在本机抽出开篇、中部、结尾候选。看过候选再保存，不上传整本、不调用模型。
2. 登记名称、作者、来源和分析使用范围；每份200—8000字符，每书最多8份、48000字符。参考正文不可覆盖，相同文本不会重复导入；归档仍保留原始来源。
3. 在原有模型配置及费用授权有效时，主动点击「分析所选参考」。策划角色1次请求生成视角/节奏/对白/细节/情绪/信息的规则、适用场景与真实短引文。
4. 选方案，填写共同场景任务，可从下一未开始章计划填入后编辑。同一写手分别写基线及参考技法版，各约1500汉字；审核匿名比较。完整对照最多3次请求，分别预留、记账、保存。
5. 阅读两版和审核意见后采用文风，采用不调用模型。只从尚未开始章生效，不改既有定稿、任务书、费用、预算或运行状态。本人核对后再启动正式创作。
6. 暂停最多保存当前请求。离开页面不发后续试写；未知中断不重放，配置/故事/来源改变会阻塞。先看已保存结果及费用，再决定是否另建实验。
7. 正式写手读取抽象文风规则和本书示范，优先衔接本书已锁原文；保留原叙述视角、人称和人物口吻。原单章审核另给至少两个文风维度的实际原文依据，不增加每章常驻角色。
8. 参考库连续40字符重合会在付费审稿前停止，这是有限文本核对，不能证明全网原创。文风和外部AI检测分不能替代编辑试读或平台签约。
9. 完整JSON备份包含参考、文风和实验记录。恢复与修订副本仍暂停，导入实验只作历史参考，不能直接续跑旧收费步骤。

可选文风实验计入本书实际成本，不含在默认90万字估算中；缓存不保证命中。软件不会替你开启费用、补密钥、换模型、恢复后台调度或发表小说。详见 docs/STYLE_WORKFLOW_V09.md。
