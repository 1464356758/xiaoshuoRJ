# V2.0.1 表单与短稿恢复修复

用户手机实际反馈：新建作品时被周期读取切回作品页；作品第二章候选只有4587汉字，未到8000—10000，普通继续返回409。

## 原因与行为

- 原生新建页沿用“作品”路由，5秒轮询会完整重建页面。现在新建/连接/编辑各有页面状态，后台只改进度文字，不重建表单、不占用操作锁。请求归属校验拒绝跨页或跨作品的迟到回调。本机保存新建与编辑草稿，显式刷新前后保留输入。
- 模型设置改为固定可见的两排导航，无需横向寻找。
- 生产只读核对：该短稿请求实际max_tokens=24000、thinking=disabled、temperature=0.8，completion_tokens=4079，finish_reason=stop。它是模型主动提前结束，不能靠提高上限或重新连接解决。开发未发送真实模型请求。
- 作品页“处理候选 / 阻塞”可直接查看私人候选、载入人工编辑（0模型请求）或本地重验。修复空章节保存人工稿时误写空hash历史版本的错误；完整人工稿仍需通过字数与正文校验。
- 完整返回且被拒绝的初稿可由本人明确确认“额外1次请求”后登记一个独立重写任务。身份从原候选派生，连点、网络超时后重复提交、进程重启都复用同一任务。原候选、usage与费用记录保留。新稿失败立即阻塞；成功保存后暂停，不自动审核，需本人再点继续。
- 未知、部分或截断结果不提供该重写入口。普通继续不会把旧步骤重新发送；已应用或已替代响应不能再次本地应用。五审次数、原已收稿章节和金额仅记账规则保持。
- 单次写作提示明确目标汉字、章内场景篇幅和结尾边界；重写在同章内扩展有效候选。提示不能保证模型总会达到字数，失败仍保留候选并停止。
