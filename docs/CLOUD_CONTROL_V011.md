## 手机必须一直开着吗？

不需要。独立安卓 App 只发送启动/暂停/设置并查看结果；常驻云服务器独立创作。服务器正常运行且任务未到目标、费用/质量门或错误时，手机退出、杀后台、锁屏、断网或关机都不停止任务。重新打开 App 后读取云端保存的进度。关闭 App、切后台和断开配对都不会发送暂停。

云服务器需要保持运行、保留数据盘和可用余额。云服务被停用、欠费或休眠时不能继续；并不是手机安装好 APK 就自动获得了一台服务器。

## Railway 部署设置

使用自己的 Railway 项目。源仓库为 `1464356758/xiaoshuoRJ` 的 `main`，根目录 `/`，自动识别根 `Dockerfile`，不要运行原 Site 的构建/启动命令。

| 项目 | 值 |
|---|---|
| 服务 | 一个常驻服务，例如 novel-factory-cloud |
| 构建 | 根目录 Dockerfile |
| 启动 | 镜像默认 CMD，node cloud-server/entry.mjs |
| 持久盘 | 新建并挂载到 /data，保留整个盘 |
| DATA_DIR | /data |
| PORT | 8080 |
| 副本 | 1，不开多区域/横向副本 |
| Serverless / 休眠 | 关闭 |
| 健康检查 | /healthz，超时 240 秒 |
| 重启策略 | On Failure，最多 10 次 |
| 停止宽限 | 150 秒 |
| 公网 | 生成 Railway HTTPS 域名，目标端口 8080 |
| PUBLIC_ORIGIN | 可省略，读取 RAILWAY_PUBLIC_DOMAIN；使用自有域名时填完整 HTTPS 来源 |

数据盘需要在正式保存数据前挂载。镜像入口先处理新挂载目录的权限，再降权运行服务。不要把 DeepSeek Key 作为构建参数或写入 Git；模型设置由 App 发到部署后的服务。

Railway 官方现已将 `railway.json` 的 Config as Code 弃用，新服务不能依赖它。本轮采用自动识别的根 Dockerfile 和上表服务设置。部署维护时先暂停任务、确认检查点，再更新镜像；建议正式创作期间关闭 GitHub 自动部署，避免源码更新打断在途请求。

首次新服务默认没有小说任务、没有模型密钥，费用开关关闭。`/healthz` 只返回就绪布尔值；访问根路径不会展示私人控制页面。

### 配对手机

1. 服务健康后，在该服务自己的私有容器终端执行 `node cloud-server/admin.mjs pairing`。
2. 将显示的 HTTPS 服务器地址和「连接凭证」填入 App 首屏。这个凭证用于控制自己的云端，**不是 DeepSeek API Key**，不要发到聊天或 GitHub。
3. 连接成功后进入「模型设置」，填写自己的 DeepSeek 官方 Key。核对模型、人民币最高单价与预算，主动保存费用授权。
4. 创建小说并先选择新增三章，点「启动云端自动创作」。任务登记成功即可退出手机；重新打开查看进度。
5. 停止时点击「暂停」并确认状态。供应商已经收到的请求可能继续完成并计费，暂停会阻止后续调用。

APK 没有内嵌固定服务器地址或凭证。配对时校验服务类型、协议与 UUID；后续服务器身份改变则拒绝执行，必须重新核对配对。仅允许标准 HTTPS 域名，不接受 IP、明文 HTTP、URL 内的密码、额外路径或非 443 端口。

## 长期运行与恢复

- 云端每约 2 秒检查已启动任务，一次推进原引擎检查点，模型耗时另计；不需要手机轮询推进。
- 达到目标、预算/质量门、配置变化、错误或未知收费时停止；不会无限付费尝试。
- 正常退出等待当前检查点，安全排队任务可在重启后沿用原目标。调用途中崩溃遗留租约或收费预留时，保留正文和账目、标为阻塞，由本人核对；不自动重复请求。
- 同一数据盘只能有一个执行器，SQLite 租约排斥第二进程；执行器失去租约后停止新操作与模型调用。不要把同一数据库跨机器共享为多副本。
- 原模型固定允许列表、禁止跳转、100 秒超时、质量门和三轮返修上限不变。
- App 没有手机前台创作服务、后台唤醒锁或关机唤醒。未实现手机推送；结果保存在云端供重新打开查看。

## 备份与保密

App 的完整 JSON 备份用于迁移稿件，不导出 Key。服务器灾难恢复还需要保留整个数据盘，包括 `novel.sqlite` 和 `server-secrets.json`。后者包含加密主密钥与控制凭证，仅存自己的私有备份；缺失时程序拒绝生成新密钥覆盖已有库。

停服务后完整复制数据目录最简单。运行时不要只复制 sqlite 主文件遗漏 WAL；使用云盘快照或 SQLite 在线备份工具。恢复后先读取稿件和费用记录，调用结果未知的任务保持阻塞。
