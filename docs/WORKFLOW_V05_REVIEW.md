# V0.5：中文长篇的创作、返修与费用审查

2026-10-15（UTC）。本报告区分已经写进软件并验证的机制、只能由模型判断的文学要求，以及尚未完成的真实样章验收。原私有工作台和D1继续沿用；不把更新软件等同于产出佳作。

## 一、角色和完整流程

| 角色 | 建议模型 | 职责和限制 |
|---|---|---|
| 策划/章节编剧 | DeepSeek V4 Pro | 选题、全书骨架、每批最多10章详纲、每章可执行任务书；在一次请求内自查，不额外开一个重复策划AI |
| 正文作者/返修作者 | 豆包 Seed 2.1 Pro | 读任务书、当前事实与相关旧稿原文后写正文；只有表达自由，不能自行改主要因果、人物知情边界和必要后果 |
| 独立审稿 | Qwen3.8 Max | 读实际全文，逐场景检查因果和后果；单章、开篇三章、每十章各有正式门；提出缺陷与原文依据，不能自己改任务书放行 |
| 程序 | 不调用模型 | 原文定位/哈希、字数/明显重复、配置版本、预算预留、状态约束、补丁合并、审核证据和返修上限 |
| 本人 | 最终决定 | 选择与授权模型/预算、检查审稿、决定是否修订或投稿；合同、平台录用和读者反馈不能由模型分数替代 |

这是分工假设，不是国内所有模型的文学能力排名；没有以此宣称“豆包最像人”已经被本项目证明。界面建议只填未保存表单，清空待填写价格并取消费用勾选；不改变服务器既有配置，不自动换模型。可继续沿用同一服务商，但同一模型换提示词不构成独立模型证据。

新书流程：选题和骨架 → 首批详纲 → 本章任务书 → 相关原文与事实 → 分段正文 → 免费预检 → 独立全文审核 → 有界局部返修 → 免费预检与全文复审 → 锁定 → 开篇三章/每十章联合审核 → 按定稿后果继续规划。

## 二、让“好看”具有具体可检查的目标

规划提示词要求故事发动机能持续产生不同选择和后果，避免只有换地图、换反派或升级。主冲突须有自洽立场和价值取舍；结局说明选择、获得及不能取消的代价。人物的外部行动目标与深层情感诉求可以冲突；对手具有自己的利益和行动。

每章的任务书必须包含：

- **承接与原因**：上一章结束的处境、为何现在必须行动；不能让下一章自动恢复既有损失。
- **具体场景**：目标、阻碍、人物主动选择、后果、参与者、地点及知情边界。默认9000汉字约六段，可由本人选择更大的分段。
- **必须和禁止的变化**：`requiredDelta`的旧值精确匹配当前事实，新增事实从null开始；`forbidden`不能与必须变化冲突。
- **本章必要性与承诺**：删除本章损失、后续悬念或关系张力；不是每章都强行升级危机。安静的关系变化和兑现缓冲也可以推进故事。
- **原文定位**：至多四个已定稿相关章号；作者实际读取可定位的原文，不只读摘要。

作者提示词要求细节来自人物处境，通过动作、对话、选择和留白塑造声音；避免辞藻堆砌、旁白替人物解释全部情绪、全员同一种聪明口吻。审核不能把辞藻密度或机械反转当质量，也不能把有效的安静场景误判成注水。

这些文学要求已进入模型输入，但程序不能证明主题有深度、人物有感染力。还需要实际样章、匿名盲读和后续长篇检查。

## 三、旧稿和长篇记忆

检索只使用当前作品、当前章之前的已锁章节，拒绝未来或未定稿内容。默认最近三章加最多四章相关摘要，上一章末尾2200字符，以及最多四份900字符相关原文。原文附章节号、hash和偏移；选中的实际内容不匹配hash就停止。明确要求的旧章优先于普通人物/事实关键词匹配。

完整当前事实保留；活跃伏笔按ID取最新状态，已兑现项退出活跃清单。最近12章结构指纹与最多六个早期相似候选供审稿参考；字面相似只是候选，不能冒充语义重复结论。

事实超过24k字符、活跃伏笔12k、整体检索包48k时停止，不能偷偷删记忆，也不能递归付费压缩。以上是容量边界，当前尚无面向用户的专用账本整理器。检索以确定性规则实现，未声称达到可靠的语义检索或整书全量回读。后续应依据真实错漏样本改进人物ID、事件时间与片段锚点。

## 四、审稿与自己返修

免费预检先拦篇幅、章内重复和明显旧文复用，避免拿必然不合格的全文先买一轮审稿。正式单章维持总分85、商业/因果/人物核心各14，重大缺陷或架构问题否决，不降标准。

V0.5新增硬门：每个任务书场景需要不同的真实引用及结果说明，必须变化须在有证据的事实变化中出现，禁止变化不可出现。空结构、虚构评分引用、虚假的伏笔兑现和原地不动的状态不允许锁定。评分引用不存在时停止，让审核错误留在审核环节，不付费修改小说迎合假引用。

自动返修只生成补丁：基稿hash一致、原文唯一定位、不重叠、最多六处，总修改规模≤正文40%（短章至少1200字符），其余文字逐字保留。范围过大、篇幅明显不可能局部修复或作者判定任务书矛盾则停止并留诊断，不自动整章重写。保留原版，每次补丁后重新全文审核；最多三轮，付费返修失败也占用尝试。本人主动请求整章修订是另一项明确收费操作。

前三章联合验收从实际原文重新判断五项追读/人物/因果/节奏/语言，85分且各项15；每十章检查全部逐章原文、阶段兑现和不可逆变化。畸形缺陷清单、非文字结论、附加虚构引用均不能通过。失败的相同稿件不会自动反复计费重审，需处理具体问题。

审核指纹绑定实际输入上下文、标题和正文。修改远期第90章细纲不重购开篇验收；开篇相关设定、人物、文风、首阶段、下一阶段或原文改变会失效。十章审核还绑定阶段开始前事实，恢复到第15章也要先补第10章门。阶段建议进入后续详纲和任务书，不能改写定稿事实。旧版已存审核可能因协议指纹升级需要一次重新核验。

## 五、钱花在哪里

| 优化 | 已实现的节省或约束 | 实际边界 |
|---|---|---|
| 滚动详纲 | 新长篇先买骨架和首批，不在开篇验证前细化完整100/300章 | 旧书保留原规划方式，绝不重建旧稿 |
| 三个角色 | 同一次策划内自查，不引入六七个常驻模型互聊 | 建议型号的效果与实际总价尚未实测 |
| 相关旧稿 | 有界检索，不每次重发全书摘要/全文 | 重要细节仍可能漏检，超过容量停止 |
| 免费预检 | 明显篇幅/重复缺陷先挡住 | 文学/语义审稿仍需付费 |
| 局部补丁 | 保留已通过段落，失败上限明确 | 结构病不能靠局部补丁治好，应停下诊断 |
| 可选大分段 | 本人可为新章选1000–3500汉字 | 可能降低重复输入，也可能增加截断；未声称已节省固定比例 |
| 各角色单价 | 独立供应商/密钥/价格，不混用账户、不自动回退 | 共用配置需填最高价格，需本人核对供应商账单 |
| 费用安全 | HTTP前同时检查当前设置版本/授权及单次、单章、单书、月度边界 | 在途请求可能已产生费用，暂停不能撤销已发请求 |
| 用量记账 | 已知usage先结算；未知/超时保守预留 | 配置最高单价记账不是正式账单，缓存折扣未计入 |

“每万字定稿成本”包含本书规划、失败调用、返修和阶段审核，不能只比较一次正文的token单价。全局规划和三章/十章审核归入单书/月度预算，本章任务书/正文/返修/复审受单章上限控制。

尚未提前预留所有未来审核资金，因此写完后也可能因余额不足留下待审稿件。阶段输入不会截断：单章/补丁上限180k字符、三章400k、十章1m；实际供应商token窗口、JSON输出和100秒超时仍需验证。没有自动重试、换模型、提高预算或降低审核门来“完成”。

## 七、下一步怎样证明作品有竞争力

1. **供应商协议验收**：由本人授权的小预算任务，逐角色验证实际型号、密钥/地区、长段JSON、真实usage、截断和阶段上下文窗口；连接成功不能代替这一项。
2. **前三章验收**：记录实际任务书→旧稿→正文→问题→补丁→复审；去掉模型和版本标签让人盲读，分别评价追读、人物动机、因果缺陷、自然语言。不能只看模型自评分。
3. **十章与十一章验收**：检查兑现、不可逆后果、中段反重复、人物信息与第11章滚动规划。前三章优秀不能证明长篇成立。
4. **受控模型比较**：同题、同任务书、相同字数/预算，只改一个模型或分段因素；比较盲读、有效缺陷、返修率、每万字正式定稿总成本。先做小样，再决定是否换组合，绝不自动替用户换模型。
5. **平台验证**：以平台当前官方AI适用政策、真实编辑反馈、合同和到账为准。软件分数不是录用、签约或保底证据，不自动发表、签约或授权版权。
