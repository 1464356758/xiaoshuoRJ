## 旧包复现与修复

| 发现 | 旧包证据 | 0.12.0行为 |
| --- | --- | --- |
| 首次读取失败后重连，编辑表单为空 | 故障注入第一次GET失败，点击重新连接后模型ID为空，尽管服务器已有型号 | 只在首次成功接纳快照时初始化配置；后续轮询不覆盖编辑草稿 |
| 未保存新密钥仍可启动旧配置 | 输入新Key、不保存、返回控制台，旧包实际发送startJob | 未保存配置会阻止登记任务，并回到模型设置，保留输入 |
| 保存期间输入被覆盖 | 延迟保存响应期间输入框仍可编辑，晚输入的Key在响应后被清空 | 保存期间锁定整个模型表单；保存请求单飞，防止重复提交 |
| 保存入口与云端运行文案混杂 | 两个保存按钮、后台登记/页面连续执行/手动执行并列，仍有保持页面打开的提示 | 模型页仅一个保存入口；独立云端仅一个启动/继续入口，保留明确暂停 |
| 默认型号变更与继承型号可能不一致 | 已存作者/审核型号可能仍指向旧值，共用密钥不等于自动清空旧型号 | 编辑默认型号/服务商时同步清除沿用角色的旧型号；独立角色保留自己的型号与单价；旧的不同型号会显式显示并可统一 |

## 配置页精修

- 用原生单选明确区分“一把密钥，三个角色共用”与“按角色分别设置”。独立模式默认带入当前服务商/型号/单价，密钥需分别填写；单个角色也可沿用策划。
- 明确区分“尚未填写”“已填写，待保存”“云端已保存”。已保存Key不回显，空框保留云端Key；从不把密钥写入浏览器持久存储。
- 切换方式时在当前会话暂存兼容的独立草稿；切换服务商清除对应新输入，绝不跨服务商复用Key。配置保存或显式重读新版本后清理旧草稿缓存。
- 单一保存栏显示费用勾选、结果和“核对云端保存结果”。未确认费用可以保存配置，但不能启动创作；缺项会在保存按钮旁指出具体角色。
- 保存成功后回读确认；服务端已接收而回读失败时明确区分，先通过GET核对，不自动重放POST。并发配置冲突保持CAS保护，保留待保存密钥，不覆盖新预算。
- 运行中的任务先暂停再改配置或测试连接。连接测试直接使用已保存配置，不再为了测试而额外保存、改变settings revision。
- 控制类请求最多等待25秒；模型步骤和较大导出保留较长等待窗口。超时、取消、迟到响应及原生取消异常不会导致永久忙碌，也不会自动重放写操作。
- 中文教程同步为当前实际按钮，手机横向不溢出；小高度视口取消粘性保存栏，避免遮挡键盘操作。

## 使用与范围

直接覆盖安装，不卸载旧版。进入模型设置，选择密钥方式、填写Key、核对费用并勾选、点击“保存模型配置”；看到“配置与费用授权已保存”后返回控制台，选择本轮新增3章并启动。

本轮没有服务端API、数据格式、主密钥、服务器身份或预算算法变更，无需部署后端。云端继续0.11.1，已有小说和手机连接沿用。真实服务器仅作脱敏只读检查：运行正常、1部作品、0章节、无任务，模型Key未保存且费用授权关闭。没有替用户修改真实配置、提高预算、启动任务或发送真实模型请求。

边界：Chromium触摸视口与原生桥接替身不等于安卓手机实机；合成供应商完成流程不等于真实DeepSeek生成质量。真实API的余额、可用型号、文学效果及用户手机安装后的表现仍需实际使用验证。
