# V0.9｜参考作品、文风规则与同题试写

本轮在原私有Site和D1上增量更新，不重建作品、密钥或安卓入口。用户明确授权实现上一轮方案；开发不调用真实付费模型，不替用户开启费用或启动小说任务。

## 手机使用路径

打开工作台，选择或创建作品，在菜单进入「参考与文风」。

1. 导入TXT/Markdown或粘贴片段。UTF-8、GB18030及带BOM的UTF-16在本机解码；较长文本在本机按章节或位置抽出开篇、中部、结尾候选，不把整本书上传到服务端。候选仅标记位置，不能冒充自动识别的高潮。查看后保存当前片段，或一并保存文件候选。
2. 填写作品名、作者和来源，确认片段的分析使用范围。每书最多8份参考，每份200—8000字符，总计48000字符。原文不可直接覆盖；相同文本SHA256幂等，归档仍保留原始来源以供旧版本检查。来源和热度由用户登记，软件不虚构“已验证爆款”。
3. 选中片段，点击「分析所选参考」。只用原策划角色一次请求，提取视角、节奏、对白、细节、情绪、信息六维技法，附适用条件、避免项及真实短引文。资料中的指令不执行，具体情节不进入本书事实账本。
4. 选择文风方案，填写同一段场景任务，可由下一未开始章的计划填入后编辑。点击「开始对照试写」：作者用相同事实与配置写基线版及参考技法版，各约1500汉字；审核角色对随机顺序的匿名稿作一次比较。最多三个请求，每步独立保存。
5. 阅读两版和审核的原文依据，确认后采用。采用本身不请求模型，不更改密钥、型号、预算、费用授权或小说任务状态。新规则从下一未开始章生效，已有任务书、正文及定稿不改。

参考分析和试写是可选实验，不能以模型自评当成读者实验、文学质量或签约证明。AI来源检测与文风、原创性、平台适用性分别判断。

## 三角色与成本

| 环节 | 配置来源 | 额外请求 |
|---|---|---:|
| 参考技法分析 | 本人已保存的策划角色 | 每次主动分析1次 |
| 基线与参考技法版 | 同一已保存作者角色 | 每次完整对照2次 |
| 匿名比较 | 本人已保存审核角色 | 每次完整对照1次 |
| 导入、查看、归档、采用、重合检查、备份 | 程序 | 0 |
| 正式章节文风审校 | 原单章全文审核，十章关注文风稳定 | 不新增常驻回合 |

沿用DeepSeek主写选择，不自动替换已保存审核模型。两次DeepSeek试写均显式关闭思考；审核按审核角色路由。若写手与审核配置相同，UI明确标记为分开请求而非跨模型验证。

所有模型请求复用原最高单价、单次/单书/月度原子费用预留与usage结算；文风实验不归属正式章节，但计入本书实际总成本。未授权、无密钥、零预算、配置变更或超限在HTTP前拒绝。默认90万字成本估算不含这些自选实验。缓存不保证命中，未知用量保守保留。

## 保存、暂停与版本

- `styleReference`保存本书私有原文，`styleProfile`保存分析及来源证据，`styleTask`保存实验检查点。均走原owner隔离，不写GitHub；公开测试只有明确标注的合成夹具。
- 模型执行以书级租约及实验状态保护，正文/审核的租约改为同时检查同书在途记录的原子CAS，避免文风调用与正式生成并发。
- 全局暂停同时暂停尚未完成的文风实验。当前在途调用最多保存一个检查点；待执行步骤不自动继续。关闭页面后不启动新试写请求。
- 上次请求中断且没有保存结果时，过期状态转阻塞，不重放未知收费调用；配置、故事、大纲或来源变化也阻塞。已完成分析/基线/增强稿保留。用户可核对后主动另建实验，每书最多40个实验记录。
- 文风以独立hash及生效章号绑定。保留本书既定叙述人称、视角、时态及人物口吻，技法冲突时以基线为准。后续切换不更改已开始章节；旧云端任务因文风revision变化而失效，需本人核对后启动。
- 开篇/十章验收指纹只纳入对应范围实际适用的文风。第11章以后采用新规则不使前十章或开篇无故重新计费。
- 本书试写锚点明确为非正式剧情，仅供表达示范。正式作者仍优先读取本书已锁原文；外部参考人物和事件不进入事实账本。

## 原创性与审稿

正式写手得到抽象规则与本书原创锚点，不反复读取外部小说全文。原有全文审稿中，启用文风的章节另给至少两个不同维度的实际原文证据；虚构引用停止，不自动付费返修迎合错误证据。重大语言问题仍走原issues和最多三轮局部返修，不提高评分或降低质量门。

本地检查正文与所选参考是否有至少40个去标点/空白字符的连续重合。发现则在付费审稿前阻塞，提示核查具体表达；试写出现重合同样停止。它只是与本书有限参考库的文本比较，不证明全网原创，不判断法律侵权，也检测不到所有语义借用。人物关系、连续情节和整体阅读体验仍需编辑判断。

## 备份和修订

完整JSON备份增加参考原文、文风方案、实验记录及生效绑定。恢复先校验hash、容量、来源、章节文风与审稿引文；不能删掉绑定把有文风证据的定稿降级成旧协议。独立修订副本复制参考和文风规则，保留原稿。

恢复和复制保持暂停。实验报告作为导入的历史记录，不能直接续跑或用旧报告为新作品采用另一个文风；需要在当前作品主动另建实验。已绑定文风和原文来源继续保留，以支撑后续阅读和重合检查。

发布前执行真实SQLite程序/协议/故障测试、TypeScript检查、Worker生产构建及实际Worker HTTP接口检查。结果完成后补记到PROJECT_STATUS和开发日志。
