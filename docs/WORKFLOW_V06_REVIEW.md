# V0.6：故事控制台与高级叙事协议

2026-10-16。继续使用原来的私有Site、D1和三个模型角色。既有作品、费用授权、模型和暂停调度不自动改变。

## 实际增加的能力

- **故事控制台**：读者体验承诺、主题问题、结局代价、当前阶段、未来三章、承诺期限、人物选择证据、实际定稿评分和旧稿原文对照。没有记录的内容明确留空，不补造人物成长或签约预测。
- **规格书**：新作品的策划需给出可持续的读者承诺、主题张力与结局代价；4–40名核心人物有稳定ID及各自目标、欲望、弱点、声音、代价和知情范围。
- **焦点人物**：每章任务书明确一个已知人物的本章欲望和取舍；正式审稿须引用真实原文说明其选择及后果。允许关系、认知、立场变化推动安静章节，不要求每场发生损失或反转。
- **伏笔状态机**：计划定义与逐章定稿事件分开保存。状态从待埋设到已埋设再到兑现；事件不能覆盖原承诺或最迟期限，已兑现项不能重新打开。
- **到期任务**：本章应埋设/兑现的承诺须进入场景任务书，审核须发现相应实际事件。缺失不能靠高分通过。明确的新承诺可用新ID登记并给未来期限，不能凭空兑现未开启项。
- **反重复证据**：任务书不能直接重复最近三章完全相同的冲突/手段/情绪组合。编辑须用本章与实际提供旧稿片段的原句对照，说明不同或相似机制；程序附上旧稿hash与摘录范围。没有旧稿可明确首章无比较，资料不足则暂停定位，不能要求作者付费伪造差异。重大结构重复停止自动局部返修。

已有逐章85分、核心各14、开篇三章联合85/各15、每十章阶段审核、三次局部返修和预算门保持。任务书、正文、独立编辑、返修仍使用原来的三角色请求，没有增加一个常驻模型或必需付费审稿回合；输入字段增多可能增加token用量，不承诺账单不变。

## 伏笔容量与证据边界

初始计划最多100项明确承诺；同一章埋设与最迟兑现的必需行动合计最多40项，与任务书上限一致。计划中的paid标记不能冒充正文已兑现；只有已锁章节事件会增加兑现计数。计划和审稿新登记承诺均检查未来容量，避免出现已付费规划却无论如何都不能开写的死路。不会自动延长期限或降低承诺内容。

原文引用存在只能证明编辑引用过该片段，不能程序化证明人物感人或结构有原创性。新增的反重复结论来自独立编辑的语义判断；字面重复硬门不声称识别所有换皮剧情。对照只覆盖本次实际提供的片段，不宣称读过全部历史全文。

旧稿检索修复了V0.5的元数据丢失：伏笔状态更新仍保留最初promise、plantChapter和dueChapter，原埋设/兑现引文可从面板回读。检索、面板和状态重放在程序内完成，不调用模型做递归摘要。

## 新旧作品与恢复

新建作品固定`workflowVersion:2 / narrativeProtocol:1`，使用schema3任务书。旧作品缺少叙事协议字段视为0，继续原有任务书和验收条件；没有批量升级旧稿，也没有修改联合审核fingerprint使旧结论无故重新计费。

备份缺字段恢复为0；高级备份必须保持工作流2、协议1与schema3一致，字符串版本、只修改书级版本或旧任务书降级都拒绝。高级定稿的任务书、人物/旧稿/承诺证据以及基础评分门在导入前由程序重新核对，不请求模型；不能只用gate.pass字段冒充通过。恢复和修订副本仍暂停，原稿保留。这里的校验不声称能阻止数据所有者重写整个备份并自行重算全部内容。
