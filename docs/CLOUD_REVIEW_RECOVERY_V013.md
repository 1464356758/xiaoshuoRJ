# 安卓0.13.0：审核与修改恢复流程

## 解决的问题

真实首章76分未达到85，且三次自动局部返修已使用。旧首页继续按钮重复startJob，只返回审核阻塞；工作室中的同步修订入口隐蔽，没有把完整反馈、修订、复审及后续任务连接起来。

## 使用

1. 同签名覆盖安装0.13.0，保留连接与作品。
2. 首页点击“查看审核与修改”，直接打开受阻章。阅读门问题、全部审稿意见与fix，展开六项评分和原文依据。
3. 选择“按审稿意见修订”，补充要求可留空，再明确点击“生成一次修订稿并复审”；或自行编辑正文，保存后点击“提交当前稿复审”。修改保存本身不发起付费审核。
4. 登记成功即可退出App。云端先完成一次编辑修订，保留原稿，再按原标准全文审核。通过才定稿，并继续已保存目标；本用户原目标为第10章。再次未通过、预算不足、接口错误均会停下。

AI修订和正式审核使用已保存的作者/审核模型及现有费用授权。不会重置三次自动局部返修或降低质量门，不自动追加编辑请求。

## 实现与恢复

startEditorRevision需要章节id、revision、baseHash、12至80字符nonce和至多2000字符的可选instruction。请求归属、原稿、设置/大纲/文风版本及费用在登记/执行时校验。job保存editorRevision ID及原目标，worker持有检查点租约执行rewrite，再走原审核状态机。同一nonce已完成、失败或运行中均不重新请求模型。新nonce只由用户新的明确修订操作创建。

输出正文缺失、截断或超出原篇幅范围时保留原稿及私有候选。暂停允许当前检查点完成，后续复审等待本人继续。中途重启沿用原unknown/uncertain阻塞策略，不自动重放；不会清除未知费用。原稿版本、书/章预算、所有权及模型路由保持。
