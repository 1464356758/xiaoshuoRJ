# V0.7 平台规则、十章修订与90万字成本审查

核查日期：2026-10-17（中国时间）。这是工程实现与假设估算，不是平台认可或真实模型文学质量报告。

## 已落实的流程

选择主平台 → 保存有来源/日期/版本/hash的规则包 → 同一规则进入选题、滚动详纲、任务书、作者、局部返修和审稿 → 单章全文门 → 前三章联合门 → 每10章全文总审 → 投稿材料检查。自动比较优先限定用户指定的四个平台；豆瓣阅读因当前AI创作政策不进入自动正文候选。原有其他平台记录仍可查看。

官方要求、编辑策略、尚未核验的条件分开。不能把“平台有AI辅助工具”推导成“允许整本自动正文投稿”。新书默认绑定；快照超过30天或规则改变在下一次付费前停止，若改变发生在途，旧结果不提交。规则改变不会自动更新本书标准、重启任务或开启费用。已有正文需从第1章建立独立修订副本核对新规则；旧书不偷偷更改叙事协议；未绑定新规则的旧验收不能直接作为本轮投稿材料依据。

## 每10章总审和返修锁定

已有每10章全文总审，本轮补齐修订闭环。单章锁是写保护，不是读保护；后章作者仍读取同一书的已锁正文、事实与hash。阶段通过是继续下一阶段的门，单章分数不能替代。

1. 每章85分、核心维度达标、原文与状态证据完整且无重大缺陷才锁。
2. 第3章之后先联合验收；每满10章，十章全文与每章证据、兑现及不可逆变化共同验收。不通过则不写下一章，同一失败稿不重复自动收费。
3. 发现第N章有问题，从最早受影响章节建立独立修订副本，原作品保持。保留N之前连续定稿；起始章可保留实际正文/手修稿作为待审候选，清掉旧review/gate/锁定及返修次数。
4. 没有任务书的保留稿，在原合同请求内交策划阅读，生成任务书后直接审核现有稿，不进入正文生成覆盖它。若核心因果改变，应选择重建该章而不是强套旧合同。
5. N之后旧正文不复制。旧未来详纲截断，按新定稿后果重规划；无法安全转换的旧计划设置执行门，用户修改前停止。旧问题按原章节/hash作为历史修订指导，新稿关闭问题需新原文证据。
6. 受影响的阶段PASS不复制。完全未改前缀的联合验收只有在实际输入fingerprint完全相同时才复用，避免无关重审。第N章新稿重新通过全文审核后再次锁定，相关十章必须再总审，之后才进入下一阶段。
7. 作者只读当前修订分支最新定稿；原作品旧下游与版本历史不进入续写上下文。

备份恢复保留平台绑定、修订执行门、问题指引，保持暂停。未完成的恢复/修订副本不能被再次恢复为可启动书；复制中断用同一幂等标识完成。同一标识不能混用不同起始章/保留选项。

## 自然表达、朱雀与质量模拟

自然表达审校并入已有作者/审核/返修请求：人物声音同质、套语密度、抽象解释过多、机械转折和空洞意象需按实际原文诊断；重大问题进入既有一票否决。程序本地给套话提示，提示不等于AI判断，不能单凭某个常见短语处罚。

[腾讯朱雀官方入口](https://matrix.tencent.com/ai-detect/)；[官方企业API说明](https://cloud.tencent.com/document/product/1552/135974)列zhuque-text/图片检测、企业套餐及EIU计费。当前只提供入口与说明，未接入付费检测，未向外部发送稿件；没有检测分数。自然表达改善不能承诺鉴别为人工，更不能改变豆瓣的创作方式规则。

[编辑模拟说明](EDITORIAL_SIMULATION_V07.md)提供明确标为合成的任务书、坏稿诊断和局部示例。程序故障模拟通过不等于文学过关：目前没有真实三角色样章、90万字实跑或朱雀实测，不预测签约概率，不承诺保底。
