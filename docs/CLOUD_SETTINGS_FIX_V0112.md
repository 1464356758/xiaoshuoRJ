# 安卓云端控制端0.11.2：模型设置保存修复

## 问题与证据

用户已填写模型并创建作品，控制台仍提示策划密钥、作者独立配置和费用授权缺失，点击保存看似没有效果。

排查时Railway服务0.11.1在线、执行器心跳正常。手机GET成功，多次POST被400拒绝。只读配置确认已有1部作品、0章节、没有创作任务，策划和作者没有保存密钥，费用授权false。原“将已保存主写切换为DeepSeek”按钮直接修改服务器settings，却只更新data而未同步编辑表单cfg的revision；下一次保存使用旧revision，被服务器CAS拒绝。通过旧revision的无效保存请求复现错误“模型配置版本已变化，请刷新核对后保存”，请求未更改数据。原错误栏位于页面顶端，手机滚到保存按钮时看不到。

## 修复

- “正文改用DeepSeek（待保存）”只改页面草稿，不再偷偷修改服务器revision；保留服务端版本检查，不能覆盖其他窗口的新配置。
- “三个角色共用上方密钥”把作者和审核设为沿用策划，只需在上方填写一把Key。配置切换后费用勾选关闭，需要本人核对后保存；不自动启动任务。
- 独立角色缺型号、费用勾选后仍缺密钥/单价时，在保存按钮旁明确显示具体角色和缺项。失败保留输入，保存成功后清空密码框并读取云端状态。
- 上方和下方保存按钮附近均显示云端已存密钥状态、费用授权和保存结果。提供“读取云端最新配置”；显式读取时仅保留服务商和业务空间匹配的待保存密钥，参数从云端重新核对。
- 保存期间暂停定时读取，避免控制请求堆积。原生回调丢失时控制请求有超时清理；不自动重放POST、暂停任务或重新调用模型。
- APK版本码12、版本名0.11.2，与0.11.0/0.10使用相同证书，支持覆盖更新。手机连接凭证和已有云端作品保留。

## 用户操作

覆盖安装0.11.2，不卸载原App。进入“模型设置”，点击“三个角色共用上方密钥”，在上方API密钥填写真实DeepSeek Key；核对型号、单价和预算，最后勾选费用授权并点击“保存全部模型配置”。看到“全部模型配置及费用授权已保存到云端”后点击“返回创作控制台”，选择新增3章并启动。

需要三个不同Key时，分别填写策划、作者、审核；独立角色需填齐自己的型号、密钥和两项单价。密钥不要发送到聊天。
